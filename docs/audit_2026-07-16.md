# Full-system audit — 2026-07-16

Scope: the whole repo at `2fc3229`, audited against the project's stated goals.
Method: 4 parallel adversarial code audits + live driving of the real MCP surface
(`resolve_tool`, `agent_status`) + inspection of the real artifacts on disk
(`env_reports/`, `_env_cache.json`). Every claim below was verified by execution
or by reading code — not from docstrings, not from CLAUDE.md.

Baseline: `pytest tests/` = **1251 passed, 1 skipped** (110s). Read that number
with §2 in mind.

---

## 0. The goals, as I understand them

1. **Any tool, however gnarly → a reproducible compute env.** Not "install a tool";
   install it so that the artifact is portable to HPC and byte-identical to what
   was validated.
2. **Scripts + user guides** so a bioinformatician can run that tool on *their* data.
3. **A solved component**: call once per tool/version, get a trustworthy artifact,
   *never look at it again*.
4. Trust must be **machine-verified, not agent-asserted** — because (3) means nobody
   is going to re-check. This is why the honesty contract exists.

(3)+(4) are the differentiator. The product is not the env; it's *not having to
wonder about the env*.

## 1. Verdict

| Goal | State |
|---|---|
| 1 — reproducible envs | **Strong.** Container-native build, install==ship, content-addressed cache, 10 real install tiers, cross-arch. Genuinely good, genuinely novel. |
| 2 — scripts & user guides | **Not built.** The only real user guide in the repo was hand-written by an agent in chat, is gitignored, and no code path can produce it. |
| 3 — solved component | **Blocked by 4.** |
| 4 — machine-verified trust | **Structurally sound, effectively perforated.** See §2 and §3. |

The engineering quality is high. The failures are not sloppiness — they are all
the *same* failure, repeated (§2), plus one missing concept (§3).

described as enforced in CLAUDE.md — and does not fire. The pattern is always the
same: a guard was made non-fatal to avoid friction, in a way that silently
disables it instead of failing loudly.

### Why 1251 green tests didn't catch any of this

`tests/test_authors_sources.py:98-99`:
```python
monkeypatch.setattr(R, "probe_authors_sources",
                    lambda tool, owner="", repo="", timeout=12: A.assess_tool_sources(...))
```
The test double **invents the `timeout` kwarg the real function lacks**. The mock
encodes the signature the caller *wishes for*; production throws. 9 tests pass
against a dead path.

This is systemic, not a one-off: **395 `monkeypatch.setattr` sites, 137 of them
lambda doubles**, none signature-enforced. The suite substantially tests the
system's mocks rather than the system.

Sharpest detail: `assess_tool_sources` already provides a proper injection seam
(`sources=`, `get_text=`, `get_json=` are parameters, designed for exactly this).
The tests bypassed the seam the code offered in favor of replacing the reference —
which is the only way this class of drift can occur.

## 3. THE CONCEPTUAL HOLE: the contract verifies integrity, never identity

Every layer verifies **"the thing we installed works."** No layer verifies
**"the thing we installed is the thing you asked for."**

Live, right now, on the real MCP surface:

```
resolve_tool("cellranger") → install_r_package(env, "cellranger", source="cran")
                             # rsheets/cellranger — an R package for parsing
                             # SPREADSHEET CELL RANGES. Not 10x Genomics Cell Ranger.
                             # (CLAUDE.md itself lists cellranger as install_release_binary.)

resolve_tool("talos")      → install_pip_package(env, "talos", version="1.4")
                             # autonomio's Keras hyperparameter tuner. Not the
                             # rare-disease pipeline this project was built around.
```
Both return `cross_namespace_collisions: []`.

Now follow either through the system. `library(cellranger)` loads fine. So it
**BUILDs**. Its evidence passes in the image, so it's **VALIDATED_IN_IMAGE**. No
accel/license claim, so **POLICY_CLEAN**. It gets a content digest, an in-toto/SLSA
attestation, an ENV.html reading *"✓ Validated in shipped image"*, a recipe.yaml,
and an Apptainer .sif on the cluster.

**A fully green, digest-pinned, attested artifact containing the wrong software.**

`grep identity` across `env_honesty.py` + `spec_writer.py` → nothing. The entire
trust apparatus rests on an unverified `tool_name → registry_entry` assumption, and
bioinformatics tool names collide constantly. This is the most user-facing defect in
the system: it is the one that hands you a bad artifact while telling you it's good,
which is precisely the outcome the project exists to prevent.

The fix is not more verification machinery — it's one new question asked early:
*does this registry entry's description/repo plausibly correspond to the tool the
user asked for?* Cheap signals exist (summary text, homepage repo, whether the repo
is bio-adjacent). Ambiguity should **refuse and ask**, not silently pick.

## 4. Goal 2 is not built

The single best user-facing artifact in the repo is
`env_reports/talos_authors.USER_GUIDE.md` (20 KB, genuinely excellent — explains
what Talos does, PED column semantics, that `.mt` is a directory, that `$HOME`
isn't writable on the cluster, that an empty result is a valid answer).

- `grep -rn "USER_GUIDE" --include="*.py"` → **zero hits**. No code produces it.
- `.gitignore:47` → **untracked**.
- It was hand-written in a chat session.

Meanwhile the *generated* Layer-2 deliverable (`RUN.html`) :
- renders **one** command (`usage.command_template: str` — the model is singular, so
  a Phase A→B→C pipeline is **not expressible even in principle**);
- documents 1 of Talos's 16 real steps and titles it "the workflow";
- renders `Command not self-tested` and *"Self-tested against 1 declared input
  shape(s)"* in the same panel (`run_dashboard_html.py:235-236`, unconditional);
- footers *"no field on this page was authored by the agent"* — false; it renders
  `description`, `usage.*`, all of which CLAUDE.md lists in `patch_pipeline`'s
  agent-authored allowlist.

**All 4 sealed workflows on disk have exactly 1 pipeline step.** The system has
never sealed a multi-step pipeline. For a tool whose stated purpose includes
"pipeline generation", that is the biggest unproven claim in the repo.

And the user's own stated preference — *"vanilla commands first; nextflow is a
bonus; the user guide = vanilla how-to first"* — was inverted: the markdown guide
was retired and a test now **enforces** the retirement
(`test_end_to_end_seal.py:225`), while Nextflow is the only orchestration renderer
that exists. There is no `run.sh`. The "bonus" shipped; the "first" didn't.

### The root cause is a category error
A **verified-run dashboard** (an audit trail: what ran, where, at what digest) was
asked to double as a **how-to** (a teaching document: what this tool does, what a
pedigree column means, what an empty result means). They have different sources of
truth. A dashboard can only render what the invariants captured. A how-to needs
judgment no invariant can capture.

"No field authored by the agent" is the **right rule for an attestation and the
wrong rule for a guide.** The system enforced purity everywhere, so the guide had
to be written outside the system — and it was. The fix is to let the guide be
agent-authored and *labelled as such*, sitting beside the verified evidence rather
than pretending to be derived from it.

## 9. On the next stress campaign

The campaign that matters is **not** more firewall probes — `docs/stress_findings.md`
shows those are already well-certified, and none of the 8 defects above would have
been caught by another one. Every defect above was found by **driving the real
surface and reading the real artifacts**, because the failures live precisely in the
gap between what the code says and what it does. So:

1. **Identity campaign (highest value).** 30 real bioinformatics tool names →
   `resolve_tool` → a human scores "is this the tool I meant?". This measures the
   §3 hole, which no invariant can see.
2. **The multi-step campaign.** Seal one real 3+ step pipeline. Everything about
   goal 2 is unproven until this exists.
3. **The anti-mock campaign.** For each of the ~10 load-bearing internal seams, one
   test that calls the real callee with injected I/O. The 137 lambda doubles are
   where the next §2-class defect is already hiding.
4. **Artifact review, not test review.** After any campaign, read the rendered
   ENV.html/RUN.html/recipe.md as a user. Three of the falsehoods in §4 and §6 are
   visible in 30 seconds of reading output and invisible to any assertion.

## 10. Tier 0 post-mortem — what the self-audit changed

Three things worth recording, because two of them correct THIS document.

**1. The audit's own I7 fix was wrong.** §2/#8 said "fix `and`→`or`". I made that change,
then drove the real host monitor and found it false-refuses real, successful steps:

```
true              rc=0 wall=0.01 peak_rss_mb=0.0 samples=1
echo hi           rc=0 wall=0.01 peak_rss_mb=0.0 samples=1
python3 -c pass   rc=0 wall=0.05 peak_rss_mb=0.0 samples=1
sleep 0.5         rc=0 wall=0.52 peak_rss_mb=1.0 samples=2
```
`env_manager._run_monitored` polls the process tree every 0.3s, so any step faster than
that legitimately reports zero RSS. That is a **sampling limit, not fabrication** — and a
value-level check cannot tell the two apart. `or` would have refused every fast host step
at seal.

The defect was real; the fix belonged in the **producer**, which is the only layer that
knows which case it's in. `cluster_jobs._parse_max_rss_mb` now returns `None` for "sacct
accounted nothing" (was: `0.0`, indistinguishable from a measurement) and
`cluster_job_resources` attaches an explicit `sacct_error`, which I7 already refuses.
`and` is retained, with a comment explaining why tightening it is a trap.

**Generalised rule, now applied in three places: absence of data must never render as
data.** Gate fails → `authors_gate_error`. sacct has no MaxRSS → `sacct_error`. SBOM probe
fails → `sbom_error`. Each replaced a silent degradation to a plausible-looking value
(no author tiers / `0.0` MB / `[]` packages) that downstream rendered as an observation.

**2. One more instance of the pattern, found while sweeping.** `freeze_from_image.py:147`
wrapped the SBOM capture in `except Exception: pass`. A probe failure left
`resolved_packages == []`, which the ENV report renders as "0 along for the ride" and the
attestation carries as an empty package list — the *headline* Layer-1 deliverable silently
vanishing. Now recorded as `sbom_error` (disclosure, not a refusal: some images genuinely
have no conda prefix). The other ~10 bare swallows in `agent/` are benign best-effort
enrichment (JSON coercion, mtime, fastq length scans) and were left alone.

**3. Fixing the gate armed the latent `route()` gap, as predicted (§6).** `route()` now
defers on `author_image`/`authors_recipe`. Blast radius is **zero for the agent**:
`route()` has exactly one caller, `build_env_from_tools`, which no MCP tool exposes, and
the agent's real path (`resolve_tool` → `install_call` → `build_env_from_authors_recipe`)
works. Its misleading "pip needs engine pypi support" message is fixed to name the real
executor; the structural fix is entangled with the Tier-4 "expose or delete
`build_env_from_tools`" decision and stays there.

**Also corrected in Tier 0 (found by self-audit, not in the original plan):**
- `resolve_tool`'s docstring — the agent's actual routing prompt — still described the
  pre-gate ranking. Turning a feature on while its description omits it is only half a
  fix. Now documents the gate, the tiers, and `authors_gate_error`.
- `submit_workflow`'s manifest root was CWD-relative while `transfer`'s was repo-anchored;
  that inconsistency is what let the `fake.example.edu` record escape. Both now use one
  anchor, so test isolation patches one function.

**On the anti-mock sweep (§9/#3):** an automated signature-drift scan over the 137 lambda
doubles produced 29 hits that are ~all false positives — doubles renaming *positional*
params (`lambda n, t=12` vs `(name, timeout=12)`) are harmless. The killer pattern is
narrower: **production passes a keyword the callee lacks**. That needs call-site binding,
not signature comparison, so the campaign stands as real work rather than a script.

## 8. The one-sentence version

The reproducible-env engine is strong and close to done; what's missing is that
**seven of its guarantees are checks that don't run, its trust contract never asks
whether the tool is the right tool, and the user-guide half of the product exists
only as a file a human wrote by hand and git ignores.**
