Two maps in one, sharing one inventory. TOP: the action-verbs a user can ask for (install an env, create a pipeline, run data, move bytes, ...) — 'wtf can this thing do'. This is step one of the determinism plan: you cannot make behaviour deterministic without first enumerating every decision.

This is a COMPOSITION (run_step ×N + the SEAL seam), not a single Kind. It is where the reference/test data (e.g. the GTF) is bound as an ExternalSource. LIMIT surfaced on Longleaf 2026-07-30: a MULTI-STEP CLUSTER chain can't be cleanly SEALED — a step that consumes a prior step's output DIRECTORY (DESeq2 reading htseq-count's counts dir) is an I8 orphan (the directory basename matches no individual file output, and the prior step's outputs are recorded as local download paths). Single-step cluster seal works (proved by samtools_cluster_rung3); directory-aware step->step lineage does not exist yet. Run-and-go is the honest close until it does — forcing the seal would mean declaring step 1's real output as 'external', a REPORTS-NEVER-LIE violation.

How much time / memory / cpus does a cluster job request?
slurm_sizing
 time & mem REQUIRED (no default); cpus/ntasks default to 1 ▲ IMPROVISED NOT caught agent/skills/workflow_render.py:121
_check_slurm requires time+mem; the agent must supply them (today: a guess, or derived from non-authoritative emulated numbers)
The system refuses to FABRICATE a measured number, but the REQUESTED sizing is an unprincipled agent guess. Too low -> OOM kill; too high -> waste. No profile-then-size loop exists. FIRST AUTHORITATIVE DATA (Longleaf 2026-07-30): htseq-count requested 8G/30min, really used 488MB/44s (~16x over on mem); DESeq2 requested 4G/20min, really used 1.28GB/25s (~3x over). Both jobs succeeded — the guess erred SAFE (over-provisioned), so this cell costs efficiency, not correctness. A data-informed default (a per-tool table seeded from sacct MaxRSS/Elapsed, or a profile-then-size loop) is now concrete and unblocked.
