# The primitives — full reference

This is the long form of the primitive table that used to live in CLAUDE.md. It was
moved here on 2026-07-31 for one measured reason: **CLAUDE.md is loaded into context on
every single session**, and this table was 8,806 tokens of it — while the operational
contract of each primitive is ALSO carried by that tool's own MCP description, which is
loaded on every session too. Two full descriptions of the same 32 primitives, both
always resident, was 21,508 tokens of duplication before any work began.

Moving text between CLAUDE.md and a docstring would have saved nothing (both load). So
the deep rationale — the war stories, the audit findings, the reasons a clause is shaped
the way it is — lives here, where it is version-controlled, greppable and one Read away,
but is not re-billed every session. CLAUDE.md keeps a routing index; the tool schema
carries what you need at the moment you call something.

**Read this file when you are about to CHANGE a primitive.** Nearly every paragraph
below is a bug someone already shipped, and the rationale is what stops it coming back.
The invariant roster remains DATA in `agent/skills/invariants.py`, and the honesty
contract tables remain in CLAUDE.md — neither moved.

| Primitive | When |
|-----------|------|
| `resolve_tool(tool, version?, github_repo?, prefer?, language?)` | **Start here when unsure which tier.** Probes conda/PyPI/CRAN (+release-binary/source if `github_repo` given), ranks and returns the concrete `install_call` + rationale + rejected alternatives. Query-only. **RELIABILITY GATE (authors-recipe-first):** two tiers rank ABOVE conda — `author_image` (the tool publishes its own image → adopt by digest) and `authors_recipe` (its own Dockerfile installs deps a conda/pip reconstruction would silently DROP: compiled/vendored/system/binary). But they are GATED, not a fixed ladder: their availability is set only when the tool's repo (explicit `github_repo` OR extracted from pip/cran metadata — so it fires automatically) actually ships an image, or when `authors_sources.analyze_recipe_completeness` flags the recipe incomplete. For a cleanly bioconda-packaged tool the gate stays shut and **conda wins** (full order: author_image > authors_recipe > conda > pip/cran/bioc > binary > synthesis > source > manual). **`author_image` availability is decided by the REGISTRY, not GitHub's package index**: an anonymous `ghcr.io/token` + manifest probe answers "can we actually pull this?", which is the fact we need — and a private image is one we could never adopt anyway, so a denial is a true negative. (It used to ask `api.github.com/orgs/{owner}/packages`, which returns **401 for every org**, public ones included, since that API always requires auth; the 401 was swallowed below the error recorder, so the top tier was 100% dead while reporting "the authors ship no image". Live now: `uv` → `author_image`, `talos` → `authors_recipe`, `samtools` → `conda`.) **A gate FAILURE is never silent and never cosmetic**: `probed.authors_gate_error` is set AND the `install_call` itself is prefixed with the reason, because a warning parked in a sibling key is a warning that gets skipped. **Cross-registry name collisions** (a PyPI `ape` ≠ CRAN's R `ape`) come back `ambiguous: true` — pass `language='python'\|'r'` to restrict the ecosystem (or `prefer` to force a tier). **ABSENT ≠ UNCHECKED at the probe boundary**: every tier's `available: false` rests on one fetch, and that fetch used to return the same `None` for "the registry answered: no such package" (HTTP 404) and "we never got an answer" (403/rate-limit/timeout). `_fetch_json` returns `(payload, error)` instead — a 404 is a *fact*, an error is `probe_error` and the tier lands in `decision.unchecked_tiers`, disclosed in the `install_call` when it outranks the pick. The collapse was never cosmetic: **one transient 403 on api.anaconda.org — nothing about the tool changed — moved `resolve('samtools')` from `conda` + a pinned `install_conda_packages(samtools=1.21)` to `binary`, recorded `conda: {available: false}` on disk, and announced "AUTO-DISCOVERED + adopted samtools/samtools (1928★) — no registry hit … proceeding without a human"** (there WAS a registry hit; every clause was false, and the ladder slid a rung into a different artifact). So an unreachable registry is **not** a dead end — discovery no longer fires on one, because reaching for the repo-search because you couldn't ask conda is the nuclear option before the investigation. Set `GITHUB_TOKEN`/`GH_TOKEN` to raise the GitHub quota 60/hr → 5000/hr: a MITIGATION, not the fix — raising a ceiling only makes the cliff rarer, never makes falling off it honest |
| `list_installed_pipelines()` | **What has ALREADY been built here — ask BEFORE solving a tool again.** Returns both layers: `envs[]` (Layer 1 — the frozen, content-addressed EnvCache entries: the reusable solved components, each with its REQUESTED tools at semantic versions read from the shipped image's SBOM, `image_digest`, `content_digest`, `build_method`, `validation_locus`) and `workflows[]` (Layer 2 — the sealed WorkflowSpecs, each pinning its env by digest, with `steps_validated` / `validated_in_shipped_image` / `usage_verified`). **`contract_ok` is EARNED at read time, not remembered**: every env is re-anchored against `env_honesty.check_build` — the same question freeze/run/stage/seal ask when serving — so `contract_ok: false` means "on disk, but the serving paths would REFUSE it today" and `contract_violations[]` names the failing clause. Query-only |
| `install_conda_packages(env, [{spec, channel}], pipeline_id)` | Anything on bioconda / conda-forge / defaults |
| `install_r_package(env, name, source, pipeline_id, deps_first?, functional_check?)` | source = `cran` \| `bioconductor` \| `github:owner/repo` — handles library isolation, BiocManager bootstrap (mirror-pinned), requireNamespace load-or-die. `deps_first` pre-installs undeclared transitive deps (the `missing_packages` retry surface drives this). **`functional_check`** = a SELF-CONTAINED R expr that RUNS the package on inline-generated data and `stop()`s if it doesn't work — becomes the freeze `VALIDATED_IN_IMAGE` evidence so *validated == ran*, not merely imported (import ≠ works: a pkg can `library()` an undeclared dep in a rarely-hit path, install+import clean, fail at runtime) |
| `install_pip_package(env, name, version?, pipeline_id)` | pip / PyPI — handles import check |
| `install_jar_tool(env, tool, jar_url, java_flags, pipeline_id)` | Java tools (Exomiser, Picard, GATK, snpEff) — auto-downloads, unpacks, writes wrapper, sets install_method.type=jar |
| `install_git_repo(env, repo_url, tool_name, ref?, build_command?, verify_command?, bin_path?, pipeline_id)` | Clone-and-run repos that aren't conda/pip/jar packages (academic script collections; C/C++ tools built with make). Clones into `{env}/share/{tool}`, pins the commit SHA, optional build + smoke verify. `bin_path` (relative path to the built executable, e.g. `seqtk`) writes a PATH wrapper AND is recorded with `build_command` so **freeze can rebuild the tool in the ship image** (source replay); omit for run-by-path scripts. Sets install_method.type=source; anchored by I11. **Pin `ref` to a tag/commit** — a bare default branch drifts |
| `install_release_binary(env, tool_name, url, sha256?, binary_in_archive?, wrapper_name?, verify_command?, pipeline_id)` | Precompiled static binaries on GitHub releases / vendor URLs (mosdepth, somalier, sylph, dorado, cellranger). Download → sha256-anchor (mismatch = hard fail) → extract → chmod → PATH wrapper. A smoke verify catches a wrong-arch binary. Sets install_method.type=binary; anchored by I14 |
| `install_perl_package(env, module, distribution?, cpanm_flags?, build_env?, pipeline_id)` | Perl/CPAN modules (Ensembl VEP plugins, niche CPAN) via cpanm. Requires `perl` + `perl-app-cpanminus` in the env. Verifies `perl -M{module} -e1`. `build_env` = `KEY=VAL` exports for XS builds linking a conda C lib (e.g. `HTSLIB_DIR=$CONDA_PREFIX`) — use `$CONDA_PREFIX` so freeze's replay resolves it in the ship image. Sets install_method.type=perl; freeze replays the cpanm build. **Prefer conda when the module is on bioconda** (e.g. `perl-bio-db-hts`, `perl-bioperl` — BioPerl-class mega-deps install far more reliably via conda); this tier is for the cpanm-only modules |
| `install_cargo_tool(env, crate, version?, binary_name?, git_url?, pipeline_id)` / `install_go_tool(env, package, version?, binary_name?, pipeline_id)` | Rust / Go tools not on bioconda. `cargo install --root {env}` / `GOBIN={env}/bin go install`. cli_which is the anchor (locally built ⇒ can't be wrong-arch). **Captures the host `rustc`/`go` version** into install_method so freeze can replay the build with the identical toolchain on the ship platform (reproducible cross-arch). **Prefer conda when available** (many are on bioconda); these are the fallback |
| `freeze(env, tools, pipeline_name?, platform?, accel?, gated?, licenses?, push_target?, pipeline_id)` | Freeze the env into a content-addressed, HPC-shippable artifact. request_key→EnvCache lookup — a hit is **re-anchored against the full contract before it is served**: the image must still resolve in the daemon AND the stored record must still pass `env_honesty.check_build` today. A record that can no longer earn its green is a MISS, so it gets re-earned by a rebuild rather than grandfathered. (This is what makes a *strengthened* gate reach artifacts frozen before it existed — pre-Tier-2 `samtools=1.21` carried `verifications: []`, failed the contract, and was served as `proven` on every hit because only image-presence was re-checked. Same posture, now applied to evidence and policy, not just presence.) `run_step_in_container` / `stage_apptainer_image` / `seal_workflow` ask the same question via `EnvCache.lookup_verified` and refuse with the failing clause named. **ADOPT-or-BUILD**: **pure conda + a published BioContainer → ADOPT by digest** (no build); **everything else → CONTAINER-NATIVE BUILD** via `env_freeze.build_env_image` — install **and validate INSIDE the ship-platform image** (one generic bake; *validated == shipped*), cross-arch included (built in-container; no host-arch conda-pack, no cross-arch refusal). Covers every tier — conda · pip (engine `--pypi`, in-lock) · cran/bioconductor (Rscript) · binary (linux asset re-fetched + sha256) · jar (download + JRE + `java -jar` wrapper) · source (clone at the pinned commit + rebuild) · cargo/go (engine toolchain) · perl (cpanm; **XS compiles against the conda perl** via conda c/cxx-compiler + an xlocale.h shim). (NOT covered: baking `stage_authored_artifact` files into the image — no tier reads `authored_artifacts` at build time. An authored file is Layer-2 provenance for I8, not a Layer-1 image input.) The build is **multi-stage**: a builder with the full toolchain → a slim runtime that COPYs only the env (identical paths) + artifacts + the `.so` runtime libs (build-essential never ships). Refuses on any honesty-contract violation (`env_honesty.check_build`: BUILT · VALIDATED_IN_IMAGE · POLICY_CLEAN), incl. I13 — a **gated** build must pass `licenses`. A biocontainer is NOT adopted when the env has non-conda installs it can't represent. Records `shipped_binaries[]` + `build_method`, the **full SBOM** (`resolved_packages` conda/pip closure + `system_packages` apt/OS layer, all versioned, read from the shipped image) + **`validation_locus`** (native/emulated — I7 timings authoritative only when native). Writes **Layer-1 deliverables rendered PURELY from the verified record** (can't be faked): `env_reports/{name}.ENV.html` (the env report — REQUESTED tools with in-image validation evidence vs along-for-the-ride deps; cyberpunk dark theme, deterministic, escaped) + `env_reports/{name}.attestation.json` (in-toto/SLSA provenance; sign with `cosign attest`) + the **build recipe in BOTH forms, ALWAYS, for EVERY install path** (build · adopt · authors-dockerfile): `env_reports/{name}.recipe.yaml` (machine-readable, self-contained — `verify_env_recipe` rebuilds it and digest-checks) + `env_reports/{name}.recipe.md` (human-readable — the runnable command sequence for a hand rebuild, `env_recipe_render.render_recipe_markdown`; branches per build_method: container-native bake · `docker pull <biocontainer@digest>` · `git clone <repo>@<commit>` + `docker build`). A frozen env is only a "solved component" if anyone can reproduce it, so the recipe is never optional — an adopt records "pull by digest", an authors-dockerfile records the pinned source + the Dockerfile verbatim. **ALWAYS-WRITTEN ≠ ALWAYS-FOLLOWABLE, and the recipe must never fake the difference** (audit 2026-07-17): a recipe missing its pin **refuses** — it prints the gap and omits the commands rather than emit a paste-ready `git checkout <ref>`/`docker pull <local-tag>`, because *a placeholder that looks like an instruction is worse than no instruction*, and the warning must never demonstrate the very string it withholds. An authors-dockerfile records `recipe_path` + `build_args` + `platform` (the executor uses `-f` and `--build-arg`, then used to DROP both — so every recipe rendered a bare `docker build .`, rebuilding the ROOT Dockerfile with the Dockerfile's own `ARG` defaults silently winning; Talos pins `ARG BCFTOOLS_VERSION`/`ARG ECHTVAR_VERSION` exactly that way). An adopt pins the **registry manifest digest** (`container_build.registry_manifest_digest`), never `.Id` (a LOCAL content id, not pullable) and never the tag it was asked for. `verify_env_recipe` rebuilds + digest-checks the **container-native** path and re-pulls-and-compares the **adopt** path; for **authors-dockerfile** it `refused`s (`freeze.recipe_verify_unavailable`) — a Dockerfile build is not bit-reproducible, so digest convergence cannot prove it, and declining to check is not the same as passing (it used to return `proven(success=True)` for a check that ran nothing). The base image is **pinned by digest** (`container_build.BASE_IMAGE`) for OS-layer reproducibility. Emits the Apptainer HPC delivery contract: registry-free `docker save`→`apptainer build docker-archive` by DEFAULT, OR — when a default registry (`config docker.registry`) or `push_target` is set — pushes the image and delivers via `apptainer pull docker://` (push failure → tarball fallback, reported in `push_status`; gated ⇒ tarball-only, never pushed, per I13). `tools` = the PRIMARY requested tools. |
| `freeze_from_image(image, tools, name, version?, build_method?, dockerfile_source?, gated?, licenses?)` | **The authors'-install-path executor** (route here from resolve_tool's `author_image` tier). Freeze an env from an EXISTING image — the authors' OWN published image, or one built from their Dockerfile — instead of reconstructing from conda/pip. A human handed a tool that ships its own image would USE it; so does the agent. **Same honesty contract**: BUILT (image+digest resolve) · VALIDATED_IN_IMAGE (each `tools[*].evidence` command must RUN the tool in-image, exit 0, reference it as a real token — echo/print cheats rejected; this is the guard the Talos reconstruction slipped: evidence must RUN, not import) · POLICY_CLEAN (I12/I13). Captures the SBOM FROM the shipped image (conda closure, else importlib for venv images) + writes all four Layer-1 deliverables from the verified record. `build_method`: `adopt-image` (author image by digest) or `authors-dockerfile` (pass `dockerfile_source`={repo, commit, tag} so the recipe records the pinned source). Uses `bash -c` in-image (respects a baked venv/conda PATH). Docker required |
| `build_env_from_authors_recipe(repo, tools, name, recipe?, ref?, version?, build_args?, gated?, licenses?)` | **The declarative sibling** (route here from resolve_tool's `authors_recipe` tier — taken when the authors' recipe installs deps a conda/pip reconstruction would silently DROP). Clones `repo` (a GitHub `owner/repo`, a full git URL, or a `file://` local mirror) at a pinned `ref` (PIN a tag/commit — a bare default branch drifts), `docker build`s its `recipe` (default `Dockerfile`), then hands the image to `freeze_from_image` (contract + deliverables). The recipe records the pinned source so the build is reproducible. Docker + git (+ network for a remote repo) required |
| `generate_user_guide(pipeline_id\|spec, freeze_request_key?)` | **Standalone Markdown export** (NOT the seal deliverable — `seal_workflow` renders the HTML run dashboard instead). Renders a runnable Markdown guide from the pipeline's PASSING, validated run — every command shown was executed + validated. `freeze_request_key` pins the env BY DIGEST. Writes `env_reports/{name}.GUIDE.md`. An opt-in escape hatch for anyone who explicitly wants markdown; the normal Layer-2 deliverable is `{name}.RUN.html` |
| `seal_workflow(pipeline_id, freeze_request_key, workflow_name?, description?)` | **Layer-2 seal.** Validate the run-side invariants (the Layer-2 table above; roster in `agent/skills/invariants.py`), self-test the `usage.command_template` (sets `usage_verified`), PIN the frozen env BY DIGEST, write a `WorkflowSpec` (`{name}.workflow.yaml`) + render the **Layer-2 run dashboard** (`{name}.RUN.html` — validated evidence grouped by compute locus + a distinct how-to panel, rendered PURELY from the verified spec; NO markdown). The env's `{env}.ENV.html` (Layer 1) is **immutable post-freeze** and is NOT touched by seal — cluster-worthiness is a Layer-2 fact carried by the RUN dashboard, never claimed by the env report. Accretion is **per-workflow-per-digest**: a run dashboard accretes loci as the SAME env is validated on more compute resources; a step whose evidence ran against a DIFFERENT env digest (a rebuild) is marked STALE, not shown green. The WorkflowSpec carries its external input sources (`test_data`/`reference_databases`/`runtime_configs`/`authored_artifacts`) **and its `service_dependencies`** (dropped before, so the artifact's I10 re-checked against nothing) so it is **self-verifying** — its I8 re-checks against the artifact alone; seal re-validates the constructed spec and refuses if it wouldn't pass standalone. Sets `validated_in_shipped_image` when every validated step ran in a shipped frozen env image (digest-matched via `run_step_in_container`) — i.e. **validated == shipped**. **Multi-env chaining**: a workflow may chain steps that each ran in their OWN frozen env; the check matches every step's container digest against the set of ALL frozen env digests (the EnvCache), and the `WorkflowSpec` records `envs[]` ({request_key, image, image_digest}). Call `freeze()` first. **Refuses** on any workflow-invariant violation, and on `seal.no_validated_run` — a draft with no step that exited 0. Every step-side clause iterates `pipeline_steps`, so with none they all fall silent at once and the walk returns clean while `derive_pipeline_status([])` yields a valid `in_progress`; the artifact used to be written green over a workflow that ran nothing. A `WorkflowSpec` IS the record of a run, so this is a refusal rather than a degrade — there is no subject for the artifact to be about. **The green tag is SPLIT**: `proven(seal.sealed)` only when I4 actually executed the how-to, otherwise `degraded(seal.sealed_howto_unproven)` — still written, still `success=True`, because a validated run with no how-to is a real record, just not the same one. The producer now always STATES `usage_verification` (`verified` / `failed` / `not_attempted` + a reason); it used to be left `None` when no `usage` block was authored, `exclude_none` dropped it from the artifact, and every reader fell back to the bare `usage_verified: false` — the two-states-in-one-bool defect returning by way of the field being ABSENT rather than wrong |
| `download_reference_database(name, url, local_path?, pipeline_id, compute_env?, remote_dir?, slurm?)` | Large DBs (>100 MB). **DEFAULT (no `compute_env`)**: watchdog-safe local download via run_in_background. **DIRECTED (`compute_env` set)**: renders a SIMPLE resumable SLURM script (`wget -c`/`curl -C -`) + `sbatch`es it so the COMPUTE node pulls the bytes (head node never moves a giant DB); lands in the env's `common_data` zone by default (`<common_data>/<name>/`), submit-and-document (returns `job_id` + manifest; poll `cluster_job_status`, seal once COMPLETE). Records a `locus:cluster` ReferenceDatabase (path lives on the cluster, never on your laptop). Seal is **locus-aware**: I5 + the sha256/size refresh verify a cluster DB OVER SSH (existence + non-empty + sidecar hash), the same observe-at-the-locus posture as the C2 `.sif` round-trip — a cluster DB that isn't there fails the seal. Reference N sources = N calls → N entries → N bound inputs at run time (the renderer binds each input's parent dir) |
| `run_pipeline_step(env, command, pipeline_id, inputs, output_types?, watch_dir?)` | Run + auto-validate every detected output in one call (runs on the HOST conda env) |
| `run_step_in_container(freeze_request_key, command, pipeline_id, inputs, output_types?, watch_dir?, data_dir?, extra_mounts?)` | **The validation-locus pivot: validated == shipped.** Run + auto-validate a step INSIDE the frozen env image (resolved from the EnvCache by `freeze_request_key`; adopted images pulled local). Bind-mounts `data_dir` at its own host path so existing absolute paths work verbatim and outputs land back on the host for validation; captures I7 IN the container (GNU `time -v` → exact peak RSS, host `docker stats` fallback); stamps the step `ran_in_container` + `container_image[_digest]`. Use this (not run_pipeline_step) once frozen, so the recorded run is the one that actually executes on HPC. `seal_workflow` then asserts `validated_in_shipped_image` when every validated step's digest matches the pinned env's |
| `stage_authored_artifact(pipeline_id, path, role, description, content?, generated_by?, language?)` | Any time the agent writes a file outside MCP — driver scripts, synthetic test data, hand-staged BAM/VCF/FASTA, transformed configs. Records content verbatim (text) or genesis command (binary) + sha256. Without this, the artifact's path is an orphan to I8 and `seal_workflow` refuses to write. |

Starts background process, polls until healthy, registers a ServiceDependency record + appends the readiness probe to its health_check_log. Satisfies I10 if the start succeeds. |

| `phenopacket_to_vcf(phenopacket_id, output_vcf)` | Materialize a single-sample VCF from a phenopacket — eliminates hand-VCF synthesis |
| `snapshot_project(project_name)` | **HPC bridge.** Walk a project's authorized directories on every compute env it touches (one-level `find`). Returns `entries[]` tagged by `compute_env`. Read-only; the agent's only window into the user's cluster filesystem. Auth: each project's `directories[]` (each entry env-tagged) lists dirs the agent may walk on each env, each with `permissions:` (`file_name_only` is the snapshot token). Phase 2.5 auto-extends the walk into the env's `agent_scratch_target` / `agent_common_data_target` subtrees for THIS project. |
| `cluster_module_avail(project, env, pattern=)` | **HPC bridge.** Discover loadable Lmod/tmod modules on the cluster so the agent can pick the right `module load X/Y.Z` line. ONE ssh hop running `bash -lc 'module avail <pattern>'`. Output parsed: drops section headers + `(D)`/`(L)` annotations + footer legends. `pattern` must be a safe token (alnum + `_+.-/`); shell metacharacters refused. |
| `upload(project, env, local_path, remote_abs_path)` / `download(project, env, remote_abs_path, local_path)` | **HPC bridge — unified transfer surface.** TWO primitives, three auth families auto-routed by where `remote_abs_path` falls: **scratch** (under `env.agent_scratch_target.path`; env-implicit grant; path must be under `<scratch>/<project>/...` for multi-project isolation); **common_data** (under `env.agent_common_data_target.path`; env-implicit; shared across projects); **project_path** (anywhere else; longest-prefix match in `project.directories[]` with the right token). Discrete capabilities: `upload ≠ download ≠ exec`. Wire protocol from `env.data_transfer.type`: `scp_head_node` (default, scp + sha256) or `globus` (encrypted, off-head-node). The call BLOCKS until the bytes are verified. For one-off transfers use `project_name="_ad_hoc"` — synthesized virtual project with scratch + common_data access on every env, no YAML edit needed. **Every call writes a human-readable `transfer_history/<project>/<YYYY-MM-DD>/<stamp>_<direction>_<hash>.json`** — leads with a plain-English `outcome` (`uploaded`/`downloaded`/`refused`/`failed`) + one-line `summary`, records the ACTUAL `command` that ran (the `globus transfer …` / `scp …` / `cp …`), human `size`/`took`, and omits fields that don't apply (no wall of nulls). The audit trail, no agent memory needed. The diagnostic for `PERMISSION_DENIED` parses `globus task event-list` and routes the actionable hint based on which endpoint reported the error (local GCP Accessible-Folders config / remote `data_access` consent / remote POSIX perms). |
| `globus_task_status(project, env, task_id)` | **HPC bridge — resolve a Globus task's real end state.** ONE `globus task show <id> --format json` query; returns `status` (ACTIVE / INACTIVE / SUCCEEDED / FAILED), `nice_status`, `bytes_transferred`, `files_transferred`, `fatal_error`. Task_id validated as UUID BEFORE any shell-out. **Where the task_id comes from**: the SYNC path — every successful globus transfer journals its `globus_task_id` into the manifest, so any transfer record is a valid input. **When to reach for it**: `upload`/`download` returned `transfer.globus_sync_wait_exceeded`. That means WE stopped waiting at the sync cap; Globus did NOT stop transferring. The task runs on server-side and this is the only way to learn how it ended — so don't assume failure and don't re-run blind (a second transfer races the first). **The outcome tag reflects the TASK, not the query**: SUCCEEDED → `proven` (success=True) · FAILED → `broke` (success=False) · ACTIVE/INACTIVE → `loop` (poll again). |
| `cluster_job_status(project, env, job_id)` | **HPC bridge.** SLURM job-state query for polling. ONE ssh hop running `bash -lc 'sacct -j <id> -P --noheader -X -o JobID,State,Elapsed,ExitCode,NodeList,Reason,Start,End'`. `job_id` validated as `\d{1,12}(_\d{1,12})?` (digits + optional `_<task>` for array jobs) BEFORE any ssh — metacharacters refused. Empty sacct output → `jobs: []` (not an error); caller distinguishes "not yet in slurmdbd" from "never existed" with a short retry. **Every row carries `verdict` (`running`/`succeeded`/`died`) + `verdict_reason`**, because for a PRODUCTION run this row IS the answer to "did my job work" and nobody classifies it for you. THE STATE DECIDES, NOT THE EXIT CODE: SLURM reports a signal death as `<rc>:<signal>`, so the rc is ZERO for every job the scheduler killed — a bare `TIMEOUT | 0:0` row reads as clean to anyone who looks at the exit code first. `succeeded` requires COMPLETED **and** `0:0`; a COMPLETED row with a non-zero rc is a contradiction and success is not the safe reading of one. Additive — the raw sacct columns are untouched. |
| `stage_apptainer_image(project, env, freeze_request_key, sif_subpath="")` | **HPC bridge.** Mode-aware HPC delivery from the EnvCache. **ADOPT** (pure-conda + public BioContainer): ONE ssh hop, `apptainer pull <sif> docker://<image_by_digest>`. **BUILD-with-push**: same shape via pushed ref. **BUILD-archive** (default for non-conda): transfer .tar via the unified `upload` primitive (routed to the **container_upload zone** — `env.container_upload_target`, NOT common_data; no fallback), then ssh `apptainer build <sif> docker-archive://<tar>`. | `run_production_pipeline(project, env, workflow_name, tool_name, command, inputs, outputs, freeze_request_key, workflow_dir, resources?)` | **The locus-agnostic PRODUCTION run — ONE verb, swap the env.** Runs a frozen env's workflow against the USER'S project data (`directories[]` path), documented like a production run. Locus-aware: a cluster path is probed over ssh and content compared against the `<path>.source.sha256` sidecar, never by hashing a reference on the head node. A divergence returns **`degraded`**, not a refusal — re-running against a newer reference is legitimate; doing it without being told is not. Omitted ⇒ `reference_check.status = not_attempted`. The verdict lands in the return payload AND the durable manifest, on both loci. **Inputs must EXIST** (both loci) — a fail-fast precondition both sibling verbs already had. This is the PRODUCTION sibling of the validation verbs (`run_step_in_container` / `run_step_on_cluster`): it DOCUMENTS the run (a manifest, findable later) but does NOT seal a `WorkflowSpec`. Auth: `workflow_dir` must be a `directories[]` path with BOTH `upload` and `exec`. Completes the run 2×2 (validate·production × local·cluster). |
